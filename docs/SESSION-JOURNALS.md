# Gameplay session journals

- On by default. Right-click Alexandra → **Open session logs…** opens `%LOCALAPPDATA%/Alexandra/Session Logs`. The same shortcut is available in Setup.
- One Markdown file per observed Elite `LoadGame` session, closed on `Shutdown`. An app restart or journal-file rollover does not start a new log. Returning to the menu and loading again starts another game session.
- Updated about every three seconds while Alexandra is open. If Alexandra closes first, the next launch catches up from available journals, including completed sessions while away.
- Starts with new activity after the feature is first enabled; it does not create logs for your entire old journal archive. Starting mid-game produces a clearly marked partial session.
- Missing shutdowns use the last observed activity, not an invented finish time. Recorded span is not an active-play timer.
- Natural-language summary, systems visited, docking, purchases/sales, materials collected, engineering work, construction deliveries and ship/commander loss.
- **Session stats** appear above the summary prose. Only positive recorded values are shown: credits received, confirmed player kills, bounty/bond awards, completed missions, CG rewards claimed, jumps, cargo sold, materials collected and losses. Empty stats are hidden. Credits received include recorded market sales, mission rewards, CG rewards, redeemed vouchers, exploration sales and organic-data sales; they are not net profit or a complete balance change. Combat award counts are not unique ship kills. See the [Frontier journal event definitions](https://hosting.zaonce.net/community/journal/v37/Journal_Manual_v37.pdf).
- **Combat after-action**: shield-down reports, main-ship/fighter hull observations, heat damage, incoming fire, interdictions, bounty/bond awards and losses. Latest 60 timestamped combat events plus totals; not a total kill counter, continuous health monitor or inferred cause of death. See [combat companion](COMBAT.md).
- Missions started/completed/failed/abandoned and recorded delivery progress come from game evidence. Personal goal changes come from explicitly saved memory edits. Say “My goal is to …”, “Update my goal …” or “I finished that goal.” Being in the right system alone never completes a personal goal.
- **Stated session plans**: clear first-person gameplay statements such as “I'm turning in old community goals, then I'm going to do combat” are captured automatically from your final voice transcript. No special command is needed. Short excerpts are kept in the current commander's current session, not a full conversation archive or a new long-term goal. Questions, tentative/negated plans and casual chat are skipped; extraction is intentionally conservative and may miss indirect phrasing.
- **Community goals and redeemed bonds**: actual reward claims, joins/withdrawals, contribution increases between observed snapshots and redeemed combat bonds. Advertised bonuses, awards not yet redeemed and globally completed CGs are not treated as received credits or proof you completed a personal goal.
- **Pick up next time** lists last-known active missions and goals. Mission information can be incomplete or expired; this is not proof of present eligibility.
- Local deterministic summaries: no additional API calls and no full conversation, audio or screenshot archive. Game-journal recaps work without cloud access. Spoken plans use the normal voice transcript, require a running loaded game and do not depend on debug logging or the memory switch. They cannot be recovered from sessions when Alexandra was not listening. Remembering new long-term personal goals still requires memory enabled.
- Files are readable personal gameplay history. Review before sharing. No commander name/FID is put in filenames; separate profiles have separate hashed session identifiers.
- Disable session journals in Setup to pause both game recaps and spoken-plan capture. Existing files remain. Forgetting a saved memory does not remove it from historical session files.
- Files are generated, so keep handwritten notes separately. Files remain until you delete them; the internal checkpoint keeps full summaries only for active or not-yet-exported sessions. Deleting a completed log normally leaves it deleted, but deleting an active log can recreate it on the next update.
- No game controls or background screenshots are involved.
