# Gameplay session journals

- On by default. Right-click Alexandra → **View session logs…** opens a local read-only journal viewer. The same shortcut is available in Setup. Files remain in `%LOCALAPPDATA%/AlexandraData/Session Logs`.
- **View most recent session log…**, directly above that item, selects the newest session in the viewer. This can be an in-progress session. Backups and temporary files are ignored; editing an older log does not make it the newest session.
- The viewer renders Markdown headings, emphasis, lists, checklists, quotes, code and tables. Text remains selectable. Web links open your browser only when clicked; HTML is never executed and remote images are never downloaded.
- Above **Summary**, generated entries use a Dextra-style status strip: muted uppercase labels, brighter values, transparent background and orange horizontal rules. Status, ship and recorded span lead; timestamps and any additional metadata remain visible. Columns reflow as the viewer is resized. This also applies to older entries without changing their Markdown files or exported copies; Summary and the rest of the entry keep their normal formatting.
- Ship types use their game display names (for example, **Federal Corvette**). Older entries get the same header cleanup when viewed or saved as a copy, without rewriting the original files. Recorded duration remains labelled **Recorded span**, without the extra timer disclaimer.
- **Search sessions** filters the session list as you type. Ship-name searches such as **Corvette** match ships recorded as used, not a ship merely mentioned in a goal. Other searches cover systems, missions, goals, dates and photo captions; multiple words must all match. Search is case-insensitive, local and read-only. **Clear** restores all sessions; **Ctrl+F** focuses search and **Escape** clears it. Refresh keeps the current search and picks up new log content.
- New entries retain all observed ship types used during a session, including switches, under **Ships used**. Older entries can only be searched using the ships they recorded; missing historical ship switches are not invented. Unreadable or unusually large logs are skipped during search with a visible count.
- Saved local photos appear in a thumbnail strip below the log. Click a thumbnail or **View photo** to enlarge it; use **Previous / Next** (or the arrow keys), **+ / −** and **Fit** to browse and zoom. **Escape** closes the photo. Missing or unreadable photos get a placeholder; the original log and images are never altered. Thumbnails load in the background, with bounded image sizes. A copied Markdown file still links to the original photos; it is not a portable photo album.
- In the photo viewer, **Copy** (or **Ctrl+C**) copies the original-resolution image to the Windows clipboard, ready to paste into an image-capable app. It copies pixels, not a file path, and does not upload or change the photo. Copy is disabled while loading or when the photo is unavailable; switching photos or closing the viewer cancels a pending copy. Clipboard-busy errors leave the viewer usable and allow retrying.
- The viewer has **Refresh**, **Open folder** and **Save a copy…** (a `.md` file wherever you choose). The displayed folder and Explorer action resolve the physical path from a directory handle, including Windows package redirection when launched by a packaged development app. It does not depend on Explorer or a Markdown file association to read the journal, and saving a copy never moves the original. No logs are uploaded.
- Personal data lives outside the install directory, so replacing or uninstalling the app does not remove settings, saved keys, memory or logs. Older data is copied automatically on first migration; originals are never removed by the migration. Conflicts are preserved under `AlexandraData/Migration Backups` without replacing current data. Back up this folder yourself if you want an additional copy.
- One Markdown file per observed Elite `LoadGame` session, closed on `Shutdown`. An app restart or journal-file rollover does not start a new log. Returning to the menu and loading again starts another game session.
- Updated about every three seconds while Alexandra is open. If Alexandra closes first, the next launch catches up from available journals, including completed sessions while away.
- Starts with new activity after the feature is first enabled; it does not create logs for your entire old journal archive. Starting mid-game produces a clearly marked partial session.
- Missing shutdowns use the last observed activity, not an invented finish time. Recorded span is not an active-play timer.
- Natural-language summary, systems visited, docking, purchases/sales, materials collected, engineering work, construction deliveries and ship/commander loss.
- **Session stats** appear above the summary prose. Only positive recorded values are shown: credits received, confirmed player kills, bounty/bond awards, completed missions, CG rewards claimed, jumps, cargo sold, materials collected and losses. Empty stats are hidden. Credits received include recorded market sales, mission rewards, CG rewards, redeemed vouchers, exploration sales and organic-data sales; they are not net profit or a complete balance change. Combat award counts are not unique ship kills. See the [Frontier journal event definitions](https://hosting.zaonce.net/community/journal/v37/Journal_Manual_v37.pdf).
- **Combat after-action**: shield-down reports, main-ship/fighter hull observations, heat damage, incoming fire, interdictions, bounty/bond awards and losses. Latest 60 timestamped combat events plus totals; not a total kill counter, continuous health monitor or inferred cause of death. See [combat companion](COMBAT.md).
- Missions started/completed/failed/abandoned and recorded delivery progress come from game evidence. Personal goal changes come from explicitly saved memory edits. Say “My goal is to …”, “Update my goal …” or “I finished that goal.” Being in the right system alone never completes a personal goal.
- **Stated session plans**: clear first-person gameplay statements such as “I'm turning in old community goals, then I'm going to do combat” are captured automatically from your final voice transcript. No special command is needed. Short excerpts are kept in the current commander's current session, not a full conversation archive or a new long-term goal. Questions, tentative/negated plans and casual chat are skipped; extraction is intentionally conservative and may miss indirect phrasing.
- **Community goals and redeemed bonds**: actual reward claims, joins/withdrawals, contribution increases between observed snapshots and redeemed combat bonds. Advertised bonuses, awards not yet redeemed and globally completed CGs are not treated as received credits or proof you completed a personal goal.
- **Pick up next time** lists last-known active missions and goals. Mission information can be incomplete or expired; this is not proof of present eligibility.
- **Photos** links images you explicitly request, with UTC time, current system, station when known, and an optional short caption in your own words. Try “Take a photo—first landing on this planet.” PNGs remain in Pictures / Alexandra; the log contains local links, not image copies or uploads. No caption is invented when you supply none. Up to 200 photo links per session. Moving/deleting a photo can break its link; review captions and local paths before sharing a log.
- If journals are off or there is no active loaded game session, the requested PNG can still be saved, but it is not linked into an unrelated or old log. No automatic photos are taken. Captions are user statements, not verified game events.
- Local deterministic summaries: no additional summary API calls and no full conversation or audio archive. Game-journal recaps work without cloud access. Spoken plans use the normal voice transcript, require a running loaded game and do not depend on debug logging or the memory switch. They cannot be recovered from sessions when Alexandra was not listening. Remembering new long-term personal goals still requires memory enabled.
- Files are readable personal gameplay history. Review before sharing. No commander name/FID is put in filenames; separate profiles have separate hashed session identifiers.
- Disable session journals in Setup to pause both game recaps and spoken-plan capture. Existing files remain. Forgetting a saved memory does not remove it from historical session files.
- Files are generated, so keep handwritten notes separately. Files remain until you delete them; the internal checkpoint keeps full summaries only for active or not-yet-exported sessions. Deleting a completed log normally leaves it deleted, but deleting an active log can recreate it on the next update.
- No game controls or background screenshots are involved.
